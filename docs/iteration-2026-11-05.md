## 使用方式

1. 找物页默认显示「在用」。详情点击「归档物品」，填写可选原因后「确认归档」；失败会保留原因，版本冲突先显示最新资料，再由用户重新确认。
2. 切换「已归档」后可查看资料、照片及历史。点击「恢复物品」，重新选择房间、容器和隔层，再「确认恢复」。旧位置被删除也可以恢复到新的有效隔层；失败保留所选位置。
3. 详情底部「操作历史」常开，按最新在前显示时间、操作者和位置名称快照，支持「加载更早记录」与「重试历史」。符合条件的单件移动显示「撤销这次移动」，成功后更新位置与历史。
4. 空间页打开容器隔层，选中隔层后编辑「隔层名称」并「保存名称」；已有自定义值时可「恢复自动名称」。调整容器尺寸或层数时，存续隔层仍保留原 ID 与自定义名称。

## 行为约定

- 找物页提供在用/已归档切换，默认仅在用。归档是可恢复操作，保留资料、照片与历史，记录原因；归档时解除当前隔层关联并保存归档前位置快照，不再阻止原柜子或房间清理。
- 恢复必须选择有效隔层，视为用户确认当前放置位置；旧位置被删除也可恢复至新位置。归档物品不允许编辑、移动、确认、替换照片，仍可查看详情、照片与历史。
- 详情按最新在前展示操作记录，包括登记、资料修改、移动、确认/未找到、照片替换、归档、恢复，以及整柜换房间。记录操作者显示名与位置名称快照。历史旧事件缺失快照时明确显示信息不完整，不把当前名称伪装成历史名称；后续改名或删除位置也不改写过去的快照。
- 最近一次单件移动且其后没有任何物品修改时可撤销，版本、旧隔层归属和存在性均校验；撤销本身生成新记录。整柜移动不作为单件撤销操作。
- 隔层自定义名称与自动名称分开，显示名称优先使用自定义值，可恢复自动名称；更改柜子尺寸/层数时保留存续隔层 ID 与自定义名称。保存使用容器版本避免覆盖同时发生的布局调整。

## 接口约定

- Item 新增 `archived_at: string|null`、`archive_reason: string|null`。归档物品 `compartment_id/room_id/container_id` 为 null，`location_path` 返回归档时位置快照。
- `GET /api/items?status=active|archived`，默认 active。
- `POST /api/items/{id}/archive`：`{expected_version, reason}`；`POST .../restore`：`{expected_version, compartment_id}`；返回 `{item}`。
- `GET /api/items/{id}/events?limit=50&offset=0`：`{events, has_more}`。事件包含 `id,type,created_at,actor_name,from_path,to_path,changes,item_version,can_undo,legacy`，路径数组或 null；changes 为字段到 `{before,after}` 的映射。
- `POST /api/items/{id}/events/{event_id}/undo`：`{expected_version}`，返回 `{item}`。
- Compartment 新增 `custom_name:string|null`、`default_name:string`。
- `PATCH /api/compartments/{id}`：`{expected_container_version, custom_name:string|null}`，返回 `{container}`。仅本家庭可修改，空白名称拒绝；null 恢复自动名称。
