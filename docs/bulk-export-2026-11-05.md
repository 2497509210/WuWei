用户确认上传可用并要求恢复既定优化计划，本轮交付多选、批量移动/归档/恢复和CSV/JSON清单导出。楼层继续暂缓，不新增箱子搬家或独立空间规划产品。沿用当前技术栈与发布流程，测试和备份后上线。

## 使用方式

1. 找物页点击「批量整理」，勾选 1–100 条记录；「全选当前结果」在结果超过 100 条时明确拒绝，需缩小筛选范围，不截取前 100 条。「清空选择」和「退出批量整理」可清除所选记录，普通详情查看保留。
2. 在用记录选择「批量移动」或「批量归档」，归档记录选择「批量恢复」。确认弹窗列出每条名称与数量；移动／恢复选择共同目标隔层，归档填写可选原因，再点击对应确认按钮。
3. 成功显示「已处理 N 条，实际更改 M 条」。移动到原隔层的记录保持不变；实际更改的记录更新版本和历史。归档保留资料、照片及位置快照并解除隔层，恢复必须重新选择有效位置并确认。
4. 一般失败保留输入；30 秒未返回或主动停止等待后，不应认定未保存。保持选择和内容不变后重试复核同一操作；内容修改后使用新操作编号。出现版本、状态或归属问题时整批不改，点击「刷新并重新选择」核对最新清单，不能直接重复旧批次。
5. 点击「导出清单」，确认范围与 CSV / JSON 格式，先「生成导出文件」再点击「下载 CSV 清单」或「下载 JSON 清单」。手机浏览器若预览文件，可用分享菜单存储；文件仅为清单，不含照片文件，不等同备份，也不支持导入。

## 批量操作

- 找物页进入“批量整理”后逐件勾选，最多100件；“全选当前结果”仅限当前已显示结果，超过100不能默默选前100。显示数量、清空选择及退出。
- 选择仅属于当前查询/状态/隔层范围，筛选变化或账号变化清空选择，避免隐藏选择被误操作；列表刷新保留选择时必须保留选择时版本，不自动抬高到别人的新版本。
- 刷新后已不在可见结果中的记录取消选择；仍可见记录保留原版本快照。保存期间禁止变更目标和选择，关闭或切换身份后的迟到响应不会覆盖当前页面。
- 在用物品可批量移动或归档，已归档可批量恢复。操作弹窗列出目标记录，移动/恢复需选有效隔层，归档原因选填。保存期间禁止变更目标/选择；失败保留输入与操作编号，同内容重试不重复。
- 后端事务内验证当前会话、家庭、全部ID、状态及expected_version。任意不存在/越权/版本或状态冲突整批不改；返回错误说明。冲突需要刷新并重新选择，不自动用最新版本重放。
- 成功时每件真正变化的物品增加版本并产生既有move/archive/restore历史；移动至原隔层视作无变更，不虚增版本。归档保留快照并解除隔层，恢复重新确认位置。
- 无返回结果/网络错误不等于未保存；同operation_id及相同内容幂等复核。批量移动仍属于独立物品move，可在当前规则满足时单件撤销；不新增整批撤销。

## 导出

- 支持“当前筛选结果”“所选物品”“全部物品（含归档）”。弹窗明确范围、格式及不含照片文件，不默默扩大范围。
- 服务器在同一只读快照和会话内验证数据归属，跨户/无效选中ID整次拒绝。导出不得包含用户凭据/邀请码或内部文件路径；只有本家庭物品清单。
- CSV为UTF-8 BOM，名称、别名、数量、备注、完整位置路径、在用/归档状态、位置确认状态/时间、归档原因/时间、更新时间、ID、是否有照片等字段；正确转义逗号/引号/换行，对以=+-@等公式标记（含前置空白控制字符）开头的用户文本使用文本化防公式执行。
- JSON保留原始值与数组，包含schema_version/exported_at/item_count/scope/items；照片只has_photo，不含二进制或私有磁盘路径。导出文件不等同完整备份，不提供导入承诺。
- 输出最多10000条，超限明确错误，不截断伪报全量。selected最多100且不为空。CSV/JSON使用attachment固定ASCII文件名、no-store、nosniff；前端先生成文件，再由用户点击链接下载，失败不保存HTML错误页。关闭弹窗或变更范围时释放objectURL，不保留旧范围文件。

## 接口合同

- `POST /api/items/actions/bulk` `{operation_id,action:'move'|'archive'|'restore',items:[{id,expected_version}],compartment_id?:string,reason?:string}`。items 1..100、ID不重复，operation_id 1..100，reason trim最大500。move/restore必须有compartment_id，archive不得带目标，非archive不得带reason，extra字段拒绝或严格语义验证。
- 成功200 `{items:Item[],processed:number,changed:number,replayed:boolean}`。items为当前记录，processed选中数，changed本次操作实际改变数；重放使用既存changed及当前记录，不重写。不同内容同ID409 operation_conflict。版本冲突409 bulk_conflict，message提示刷新重新选择；前端不用current自动覆盖。不存在/越权统一404 item_not_found。
- 新建007_bulk_operations表保存家庭+operation_id指纹、ids、processed/changed，用BEGIN IMMEDIATE保证并发幂等。
- `POST /api/inventory/export` `{format:'csv'|'json',scope:'filtered'|'selected'|'all',status?:'active'|'archived',q?:string,compartment_id?:string,ids?:string[]}`。filtered默认active且使用与listItems相同短中文/literal substring semantics；selected仅ids，无其他筛选；all包含active+archived，无其他筛选。
- 后端可抽共享item filter/serializer逻辑，不能让查询和导出语义分叉。批量与导出可复用现有serializer但导出移除photo_url并加has_photo/created_at。
