# 日常整理效率迭代

用户批准按优先级完成六项，沿用React／FastAPI／SQLite；不增加楼层、搬家产品或异机备份。所有交互在临时数据验收，推送并部署。

1. 编辑只提交本人变动字段；409以开始编辑时的基线、当前草稿、服务器最新值合并，未改字段保留服务器；双方对同字段改成不同值时逐项选择。核对后明确保存，连续冲突重新核对，不自动覆盖归档记录。
2. 房间编辑、批量归档原因及移动／恢复目标接入现有草稿保护。关闭、Escape、导航、刷新均遵循保护；取消或加载最新若丢输入须明确确认，保存中不因后退取消未知结果。
3. 新增成功提示提供查看刚登记物品，批量登记提供刚登记清单，可打开任一详情核验。保留原有筛选；若不在当前页说明可能受筛选／页码影响，不暗示保存失败、不强行清空筛选。
4. 拍照新增保存并继续，成功才清名称／照片并重置下一件操作编号，保留位置和最近保存回执。近期位置最多5个，仅保存账号家庭隔离的ID，兼容旧单位置；显示名称与选择均实时核验，永久失效剔除，临时网络失败可重试。
5. 点击详情照片进入全屏查看，支持放大／缩小／重置、键盘和触摸缩放／拖动，继续使用鉴权原图；加载失败明确提示，退出返回原详情与焦点，不干扰草稿保护。
6. 页面从后台返回超过60秒时核验最新列表；网络恢复及时核验，聚合重复事件并限制频率。无编辑时保留筛选与滚动刷新；存在详情／登记／批量选择或弹窗时先提示可能有更新，等待当前操作结束，不替换草稿、不抬高选择版本。成功刷新才清提示，失败保留旧数据与既有禁写保护；没有自动重试写入。

验收按1至6逐项确认：先失败用例再实现，独立审查，Windows／Linux回归与Chrome端到端。部署继续使用已验证的后台发布机制，核对提交、文件哈希、健康、原数据及已有备份。本轮预期不改变数据库结构。
