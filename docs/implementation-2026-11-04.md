# 物位：分层定位、位置维护与可靠性

用户已授权先比较三条路线并给预览，然后实施建议 2、3、5，并明确家庭找物作为独立页面增加，另外两条路线暂不需要。保留 React / FastAPI / SQLite 和现有空间默认入口；新增 `/find` 家庭找物页面，生产前缀下为 `/wuwei/find`。箱子清单、搬家及独立空间规划产品暂不开发。

## 本次行为

- 家庭找物独立页面：名称、别名、备注搜索；物品详情显示完整位置路径、照片、最后确认时间、确认/未找到状态。支持直接打开、刷新、前进后退；未登录时先登录，完成后保持找物页。两页均按需加载，空间与物品通过位置互相跳转。
- 空间页面：房间 3D / 平面切换，选择容器后查看二维隔层；从搜索结果定位房间与容器。
- 登记：选择一次隔层，多行批量录入（支持将一组物品作为一条记录），失败保留输入，重复提交使用幂等操作 ID。
- 维护：编辑名称、别名、数量和备注；上传照片；移动至其他隔层；确认在此处/这里没找到。移动与历史记录在同一事务，版本检查避免陈旧客户端覆盖。
- 整箱移动至其他房间保留隔层及物品身份。此次不引入任意层级的位置树。
- 稳定性：修复房间请求竞态、保存状态/失败回滚与重试、登录空格限流、直角旋转约束；非空房间禁止直接删除，缩小房间不得截断容器。
- 运维：可验证的备份/恢复脚本、每日备份 systemd timer 文件、文档；后续用户授权部署，已发布并启用每日备份。
- 访问入口：`2026-11-04-m2.3-tailnet` 新增持久化的 Tailnet HTTPS 443 `/wuwei` 路由。已连接 Tailscale 的设备使用 [内网空间](https://bd-a.tail3c54de.ts.net/wuwei/) 或 [内网找物页](https://bd-a.tail3c54de.ts.net/wuwei/find)；其他设备保留 [公网入口](https://bd-a.tail3c54de.ts.net:8443/wuwei/)。443 原有根路径到 7863 的服务保持运行，8443 Funnel 保留。
- 加载：按需载入 3D，低性能设备可使用二维视图。

## 数据与接口

在现有数据库上增量迁移，保留原房间/容器/隔层/物品 ID。items 增加 aliases、version、location_status、last_confirmed_at；容器增加 version。GET /api/items 支持 q 和 compartment_id；POST /api/items/batch；PATCH /api/items/{id}；POST /api/items/{id}/confirm、/missing、/photo；GET /api/items/{id}/photo。所有资源校验家庭归属，图片重新编码并通过鉴权接口读取。

## 验证

先运行回归测试证明当前竞态和缺失能力，再实现。覆盖批量原子性和幂等、跨户权限、图片校验、版本冲突、移动事务回滚、旧数据库迁移、删除保护、搜索请求乱序、失败保留输入、隔层选择、布局测试及生产构建。备份在临时示例数据库上做备份与恢复核验，不改已有数据。

最终结果：后端 47 项、前端 40 项、备份 10 项通过；真实 Chrome 在根路径和 `/wuwei` 前缀下分别完成 19 项流程检查，覆盖独立页面导航及登录、桌面和 390px 手机布局、照片读取、整柜移动、失败重试及刷新后持久化。手机尺寸面板等待保存成功再关闭，失败保留修改。此前三条路线预览已检查 1024px / 360px、浅色 / 深色主题和主要交互。

生产构建通过。加入独立路由后的首屏主脚本约 280 KB（gzip 90 KB）；找物页面约 12 KB，空间页面约 26 KB，3D 场景约 988 KB，均按需加载。构建仍有 3D 分块体积提示。

备份部署文件已修正目录权限和 SQLite WAL 共享内存访问。用户授权后已发布物品功能，当前版本为 `2026-11-04-m2.3-tailnet`。本次部署前备份通过校验，新增内网路由及双入口 Origin 配置；本机使用原代理环境，以及绕过代理并通过 MagicDNS 解析至 Tailnet IP 的 HTTPS 检查均返回健康接口 200，TLS 校验通过。首页、找物页及 JS/CSS 返回 200，物品接口未登录返回 401；两种合法 Origin 均通过来源校验，不可信来源返回 403。服务器内网 smoke 全部通过，`wuwei-tailnet` enabled / active；Linux systemd 下本次首次备份成功，timer 保持启用。443 原有根服务保留且未开放 Funnel，未更改网络 ACL。未使用真实账号登录；新 443 入口的线上浏览器访问同样被既有权限策略阻止，未绕过，因此没有宣称线上浏览器验收。具体结果见 [部署记录](deployment-2026-11-04.md)。
