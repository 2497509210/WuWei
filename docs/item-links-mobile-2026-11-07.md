# 物品链接与手机浏览器兼容

用户同意上一轮建议，先落实优先的1、2项。重复登记提示、按位置盘点及批量标签打印留作后续候选，不纳入本轮。

## 物品专属链接

- 地址为`/items/:itemId`（部署时带`/wuwei`）；链接只包含物品ID，不含搜索、名称、邀请码或认证信息。
- 详情提供复制入口，默认当前域名，在已知部署主机可选择Tailnet或公网；复制受限时显示可手动选择的地址，异步旧复制结果不得覆盖新入口状态。
- 直接打开、刷新、登录失效后重新登录、通过邀请码加入后均可继续访问原目标；先由鉴权API读取最新资料，再使用现有详情／编辑／照片交互。归档可查看，不存在与无权访问按受保护错误处理，不建立公开分享权限。
- 关闭返回当前账号找物上下文；空间定位用实时位置。外部链接在新账号登录后实时鉴权，应用内旧账号历史不得恢复旧搜索、资料或错误。

## 浏览器兼容验收

- 使用现有Playwright版本的Chromium和WebKit运行同一套移动关键流程；明确浏览器引擎，不以Chrome替代WebKit结果。
- 覆盖360／390px布局、登录、合成照片选图和保存、读取失败／草稿保留、浏览器返回、筛选刷新、图片缩放、清单下载及联网恢复。物品链接验收也在两个引擎运行。
- Linux CI安装对应浏览器，分目录保存失败证据。保持原有核心Chrome流程。
- 真机摄像头、手机软键盘遮挡、系统文件下载与主屏安装需要设备验收，自动化结果不宣称覆盖这些项目；编写明确的未验收清单，不使用真实生产家庭数据做写测试。

新行为先失败测试再实现；互相独立审查、回归和CI通过后推送部署。保留原备份与权限边界，不新增依赖或数据库迁移（除非验证表明必要）。

## 实现与本机验收

- 已实现物品页面及详情链接入口，新增16项路由测试、17项链接测试；前端合计354项通过（另新增1项WebKit焦点差异回归），TypeScript及生产构建通过，无新增依赖或迁移。
- Chromium和真实WebKit的物品链接流程各14项通过，覆盖真实登录、邀请码、会话失效、跨家庭404、归档、手动复制和草稿保护。
- 手机兼容流程在两引擎分别验证360／390px视口，各33项检查完成；Windows WebKit两个下载落盘场景明确列为未验证，实际文件下载仍由Linux CI严格验证。
- WebKit实际发现点击照片触发器不会必然转移焦点；新增测试复现后，改为显式记录照片按钮作为大图关闭的返回焦点，保留父表单草稿。修复后两引擎流程通过。
- 路由、复制状态及焦点修复已独立审查。真机待验收范围记录在单独清单，未冒充设备验收完成。
- 本机Windows的随机端口分配曾落到浏览器禁用的6667／6668，HTTP健康探测因而失败；临时浏览器夹具统一使用可绑定的高位端口，应用代码不改变端口或安全策略。
- Linux CI另外复现了快速连续切换搜索、状态、房间时，尚未提交的路由状态被后一操作覆盖。新增同一事件批次回归先失败，再将用户事件的筛选与URL及时同步；异步位置核验和页码修正保持异步。跨房间自动清隔层也统一参与下一次筛选合并，避免随后输入恢复旧隔层。原历史、滚动、选择和读取可信状态回归保留。
