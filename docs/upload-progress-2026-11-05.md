# 拍照上传进度与减小传输量

用户反馈上传慢且无法判断是否停住，暂停其它优化。本轮聚焦拍照保存链路，沿用既有授权验证后发布。

当前状态：**已于 2026-11-05 14:23（北京时间）发布 `2026-11-05-m3.3-upload-progress`，线上核验通过**。所有其他优化规划保持暂停，不开展批量整理、导出或其他新功能。

## 行为

- 选择照片后显示「正在处理照片…」，允许取消、换图，并继续填写名称和位置；处理期间不允许保存旧照片。只接受既定 JPEG / PNG / WebP、8 MiB / 2000 万像素范围。长边不超过 1600 像素且文件不超过 400 KiB 时保留原文件；其他照片尝试缩至长边 1600 像素、JPEG 质量 0.82 编码，仅结果更小时替换。显示原照片与待上传大小，处理一次后缓存同一 File，原样重试不重新压缩，保持指纹不变。
- 使用浏览器真实上传事件展示已发送量、总量可用时的百分比、实际总平均速度与耗时。无可计算总量时显示不定进度，不编造百分比；百分比不会随时间自行增长。
- 点击保存及切换到服务器确认阶段时，手机将状态和「停止等待」按钮滚动到可见区域，避免进度出现在折叠区外。
- 浏览器上传完成后显示「照片已传完，等待服务器确认保存」，仅业务响应成功才视为保存成功。超过 10 秒无新增上传进度时，提示「已 X 秒没有新的上传进度，可继续等待或停止等待」；这是观测到的间隔，不能据此断言挂死或服务器未保存。
- 上传阶段30秒无新增字节才结束等待，持续缓慢但前进的传输可继续；请求发送完成后的服务端确认等待90秒，整次传输最多10分钟。保留主动停止和不确定结果提示，原样重试沿用操作编号。
- 所有取消、卸载、换图与迟到回调处理保持隔离；原始照片仍只存在用户选择的本地File中，不上传调试服务。

停止等待和超时都不等于服务器撤销保存。提示要求保持内容不变后重试，核对同一次登记，避免重复创建；修改名称、位置或照片会使用新操作编号。成功仅由最终业务响应确认，不以进度 100% 代替。

## 验证

前端 **162 项测试全部通过**，TypeScript 检查和生产构建通过。传输层通过受控 XHR 事件验证阶段、未知总量、30 秒无进度、持续进度不受整次 90 秒限制、90 秒服务器等待、10 分钟总限、取消及迟到事件。照片处理测试覆盖边界、取消、换图、超时、仅采用更小结果；界面测试验证真实字节数、速度、耗时、停顿提示与处理后原样重试。

Chrome 专项验证同时通过：慢网上传流程 **6 项**、照片保存等待流程 **5 项**、既有手机入口流程 `m5` **14 项**，以及照片处理 helper **7 个场景**。手机保存后自动显示状态的检查经历真实失败、修复、再通过。
