## 第一阶段：版本管理

- 源码、测试、部署脚本、文档纳入同一Git项目，迁入repo内tests；不纳入运行数据、照片、令牌、依赖目录、测试产物和数据库。
- GitHub main为正式历史，按可审查的阶段提交，推送前核对内容与测试。不得覆盖远端已有提交。
- 后端锁定直接/间接依赖并带哈希，前端npm ci使用package-lock；每个发布版本独立Python虚拟环境。当前链接与systemd指向同一release，回滚一起回到原环境。
- CI使用Linux/Windows验证后端、前端、构建；仓库克隆后不依赖原工作区绝对路径。Linux验证发布脚本的失败回滚行为。

## 第二阶段：界面、筛选、照片和分页

- 首页压缩欢迎区，搜索/拍照/登记靠前；刷新、导出、添加桌面收至“更多”菜单，批量入口仍清晰，手机首屏尽量显示首条物品。
- 在用/待找回/已归档切换，待找回=active且location_status=missing；房间筛选仅在用/待找回有效，归档清空room筛选。保留当前隔层筛选，跨房间选择时清除隔层，导出筛选语义一致。
- 正常UI列表每页40条，服务端过滤、排序并LIMIT/OFFSET，返回total/has_more；提供上一页/下一页及范围。切页/筛选清选择，不能把隐藏页选中项用于批量；“全选当前页”明确只当前页。失败保持既有可信状态保护。
- GET items新增可选page(>=1)、page_size(1..100，page提供时默认40)、room_id、location_status；不带page/page_size兼容旧API全量。返回items及分页时total/page/page_size/has_more。q保留短中文/Unicode casefold/字面%_，搜索排序为名称完全匹配、名称前缀、名称包含、别名包含、备注包含，然后updated_at DESC/name/id稳定排序。
- 过滤和排序移至SQLite执行，避免全量序列化后过滤；使用每连接注册的deterministic casefold函数与参数化instr，相关范围索引。保留SQLite，量化1000/5000数据页查询、传输记录数及中文搜索结果，不引入新搜索服务。
- 导出filtered支持room_id/location_status，与列表共享查询规则，all/selected原语义保持。UI分页不限制“当前筛选结果”导出范围，明确导出所有匹配记录而非仅本页。
- Item新增thumbnail_url；GET photo?variant=thumbnail提供最大320px鉴权JPEG，列表用缩略图、详情用原照片。缩略图缓存置data/cache而非media，基于不可变photo文件标识，旧图替换不返回旧缓存；跨家庭/未登录无可用cache读取，禁用公共URL，不扩备份。
- 本机选图输入限额增至25MiB，现有20MP像素限制保留；符合格式的大文件先本机缩图，处理后上传仍<=8MiB。小图能保留原File，大图无法压到上限时明确拒绝，无静默丢失/无限处理；照片预览、取消、超时及原样重试保护保持。
