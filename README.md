# 物位 · 家庭物品定位

用「楼层 → 房间 → 容器 → 隔层」记录物品的位置。保留 React / FastAPI / SQLite，在现有空间模型上补齐找物、登记和位置维护。

## 路线与当前状态

在现有空间页面之外增加独立的「家庭找物」页面。默认入口仍为「空间」，可从顶部进入「家庭找物」；找物页可直接打开、刷新或使用浏览器前进后退。箱子清单、搬家及独立空间规划产品暂不开发。建议 2、3、5 已整合到本地实现：

- **分层定位**：按名称、别名、备注搜索物品，显示完整位置路径；搜索结果可定位房间、容器和隔层。空间页默认平面图，可切换按需加载的 3D，并查看二维隔层图。
- **位置维护**：选一次隔层，多行登记物品或一组物品；编辑资料、数量和别名，上传照片，移动物品，标记「就在这里」或「这里没找到」。整箱换房间保留隔层及物品 ID。
- **可靠性**：批量登记原子提交与幂等重试，物品版本冲突保护，移动与历史记录同事务；房间请求和保存有顺序保护，并统一筛选可信状态、请求期限、登录失效处理和删除版本保护。备份可校验、恢复，并提供每日 timer。
- **日常管理**：物品可归档并选择新位置恢复，详情提供可分页的操作历史和受版本保护的单件移动撤销；隔层可自定义名称，并恢复自动名称。
- **房间与账号**：管理员可在桌面和手机编辑房间名称及尺寸，保存带版本检查；独立「账号与家庭」页提供昵称、密码、设备退出、邀请及成员管理。本轮暂不开发楼层管理。
- **手机入口**：拍照登记支持原生相机或文件选择，带出本账号最近成功使用的位置；容器和隔层可生成二维码标签，扫码后仍需登录。可按浏览器提示添加到手机桌面，在线使用。
- **批量整理与导出**：最多选择 100 条记录，统一移动、归档或恢复；可按当前筛选、所选记录或全部物品导出 CSV / JSON 清单。

## 怎么用

1. 从默认入口登录后进入「空间」，首次使用先新建房间并添加容器，尺寸以厘米填写。顶部「家庭找物」打开独立页面 `/find`；内网为 [家庭找物](https://bd-a.tail3c54de.ts.net/wuwei/find)，未连接 Tailscale 时使用 [公网找物页](https://bd-a.tail3c54de.ts.net:8443/wuwei/find)。直接打开找物页后登录会留在该页。
2. 在平面图或 3D 中选择容器，打开「查看隔层与物品」，选择具体隔层。3D 的「正视」可聚焦选中容器；性能较低的设备可以一直使用平面图。
3. 打开「家庭找物」点「登记物品」，依次选择房间、容器和隔层，每行填写一件物品或一组物品。每批最多 100 条，每个名称最多 120 字。同一弹窗中原样重试会复用操作 ID，失败时保留输入。
4. 搜索名称、别名或备注，打开详情查看照片、位置路径和最后确认时间。可编辑资料、添加照片、移动位置、确认在此处或标记未找到；「在房间中定位」会选中相应容器及隔层。
5. 在容器隔层弹窗中，可将整个容器移动到其他房间。房间必须容得下该容器；已有隔层及物品身份保持不变。
6. 空间页可修改容器尺寸和层数、按 90° 旋转；3D 的布置模式支持拖动及靠墙吸附。保存失败时查看提示并重试，版本冲突需先加载最新记录，再重新确认修改。
7. 暂时不用的物品可在详情点「归档物品」，填写可选原因并「确认归档」。归档保留资料、照片、历史和归档前位置快照，同时解除当前隔层关联，不再占用原隔层。在找物页切换「已归档」查看；归档详情为只读，点「恢复物品」后必须重新选择有效隔层，再「确认恢复」。原房间或柜子已删除，也能恢复到新位置。
8. 详情下方「操作历史」按最新在前显示操作者、时间、当时的位置名称和修改内容，可「加载更早记录」；加载失败可重试。历史位置不会跟随房间、容器或隔层改名；旧记录缺少操作者或位置快照时标注信息不完整，不补造历史。仅最近一次单件移动且之后没有物品修改、原隔层仍有效时显示「撤销这次移动」；撤销会新增记录，整柜移动不在单件撤销范围内。
9. 在空间页选择容器并打开隔层，选中隔层后编辑「隔层名称」并「保存名称」。自定义名称与自动名称分开保存；调整尺寸或层数时，存续隔层的 ID 和自定义名称保持不变。点击「恢复自动名称」可撤销自定义命名；保存会检查容器版本，失败保留输入。
10. 管理员在桌面点「编辑房间」，手机点「房间设置」再点「编辑房间」，修改名称、宽、深、高后「保存房间」。名称会去除首尾空格；宽深为 100–2000 cm，高为 200–400 cm。失败保留输入；其他设备已经修改时，须先点「加载最新房间」再重新编辑。成功后导航名称与场景同步，普通成员只读房间设置。

上述第 10 项及下方账号功能已随 `2026-11-05-m3.0-accounts` 上线。

仍有关联在用物品的隔层、容器和房间不能直接删除；归档物品已解除关联，不再阻止原位置清理。缩小房间不能让容器越界。当前位置结构为固定四层，不支持任意深度嵌套。

拍照登记接受最多 25 MiB、2,000 万像素的 JPEG／PNG／WebP 原图，本机先尝试缩图，实际上传仍限制为 8 MiB；不能压到上传上限时明确提示。服务端校验后重新编码为最长边不超过 2,000 像素的 JPEG。列表读取最长边 320 像素的鉴权缩略图，详情保留原照片。照片不作为公开静态文件提供，派生缓存位于 `data/cache`，不纳入照片备份。

## 找物筛选与分页

- 手机首屏优先显示搜索、拍照与登记；刷新、导出、添加桌面放入「更多」。
- 「待找回」显示在用且标记为「这里没找到」的物品，可与搜索、房间和隔层范围组合。选择另一房间会清除原隔层范围；切换归档时清除房间筛选。
- 列表每页 40 条，显示总数与当前范围。切页或改筛选清空批量选择；「全选当前页」只选择本页。导出「当前筛选结果」包含所有匹配记录，不受当前页限制。
- SQLite 执行过滤、排序和分页，搜索优先名称完全匹配、名称前缀、名称包含、别名、备注。保留中文单字与字面 `%`、`_`、Unicode 大小写匹配。
- `GET /api/items` 支持 `page`、`page_size`、`room_id`、`location_status`；有分页参数时返回 `total/page/page_size/has_more`，单页最多 100 条。不传分页参数保留原 API 兼容行为。

## 连续操作与草稿保护

本轮日常效率改进的范围见[迭代记录](docs/daily-efficiency-2026-11-06.md)：

- **字段级核对**：编辑仅提交自己修改过的字段。版本冲突时，未修改字段保留服务器最新值；双方对同一字段改成不同值时，逐项选择自己的修改或最新值，再明确继续保存。继续使用版本检查，核对期间再次变化会重新提示。
- **其余表单保护**：房间编辑、批量归档原因及移动／恢复目标也有关闭、取消、Escape、刷新和返回保护；冲突后的加载最新／重新选择会先确认放弃输入。
- **登记回执**：保存后可直接查看刚登记物品，批量登记提供本次全部物品入口。原搜索、房间、状态和页码保持不变；新物品未出现在当前页时说明筛选／页码影响。
- **连续拍照登记**：点击「保存并继续」，服务器确认成功后清空本件名称与照片、保留位置并把焦点返回名称；下一件使用新的操作编号，同名同位置也可登记为另一件。失败、停止等待和原样重试不清空本件内容。
- **最近5个位置**：文字／拍照登记可快捷选择最近使用的位置；只按账号和家庭保存隔层ID，名称和位置每次实时核验。已删除或无权限的位置会移除，临时读取失败保留并可重试，兼容原单个最近位置。
- **照片查看**：点击详情照片进入全屏，使用放大／缩小／重置、键盘`+`／`-`／`0`或双指缩放，放大后可拖动查看；Esc关闭后回到详情。仍通过鉴权接口读取，加载失败可重试。
- **返回后核验**：距离上次成功读取超过60秒，再返回页面时核验列表；网络恢复也会触发，重复事件合并并限频。正在打开详情／登记／导出或批量整理时先提示，当前操作结束后再刷新，不替换草稿、不更新已选记录的确认版本。读取失败保留旧结果和既有禁写保护，不自动重试写入。

- 找物地址保存搜索、状态、房间、隔层和页码，刷新或分享可恢复范围；从账号、空间定位返回时恢复浏览位置。临时浏览位置按账号与家庭隔离，退出清理；不同账号不能继承应用内历史中的旧搜索。
- 详情「添加 / 更换照片」先显示本机压缩后的预览和大小，再点击「保存照片」。和拍照登记共用25MiB原图处理、真实上传进度与分阶段期限。取消等待或响应丢失后保留待传图，同内容重试核对同一操作，避免重复照片历史；取消不代表撤销服务器保存。
- 登记、编辑、移动、归档和待传照片有未保存内容时，关闭、Escape或离开页面会提示。草稿和照片不写入本机持久存储；浏览器刷新提示能力仍取决于浏览器。明确放弃、关闭页面或会话失效后不能恢复未提交草稿。
- 编辑遇到版本冲突时保留自己的输入，并显示最新资料；点击「核对后继续编辑」后再保存，才使用新版本提交。换图冲突同样要求明确核对，归档记录不能继续替换照片。
- 请求失败提示可含32位诊断编号。向维护者提供该编号和发生时间即可关联服务器记录，无需发送照片或账户密码。

## 批量整理与清单导出

以下功能已随 `2026-11-05-m3.4-bulk-export` 上线：

1. 在「家庭找物」点击「批量整理」，逐条勾选；可「全选当前页」「清空选择」或「退出批量整理」。界面每页 40 条，切页清空选择；底层批量接口上限仍为 100 条。普通点击物品仍可查看详情。
2. 在用记录可「批量移动」或「批量归档」，已归档记录可「批量恢复」。弹窗列出所选名称及数量；移动和恢复必须选择有效隔层，归档原因选填。移动到原隔层不增加版本或重复写历史，结果会显示处理数与实际更改数。
3. 归档保留资料、照片、历史和位置快照，同时解除当前隔层关联；恢复到重新选择的隔层，并确认位置。每件真正变更的物品各自增加版本并写入历史；符合现有条件的单件移动仍可单独撤销，不提供整批撤销。
4. 搜索、在用／归档、隔层或账号范围变化会清空选择。刷新清单保留仍可见记录的选择时，继续使用选择当时的版本；不会自动采用他人的新版本。任一所选记录不存在、越权、版本或状态冲突时整批回滚，必须「刷新并重新选择」，不自动用新版本重放。
5. 一般失败会保留输入与操作编号；等待超过 30 秒或主动「停止等待」只说明尚未确认结果，不代表未保存。保持所选记录和内容不变再重试，会核对同一次操作；改变内容会生成新操作编号。
6. 从「更多」点击「导出清单」，明确选择「当前筛选结果」「所选物品」或「全部物品（含归档）」，选择 CSV 或 JSON 后「生成导出文件」，再点击对应下载链接保存。当前筛选包括房间和待找回，导出全部匹配记录；上限 10000 条，超限会报错，不截断伪报全量。所选范围要求 1–100 条。失败不会把 HTML 错误页当作清单下载。

CSV 为带 BOM 的 UTF-8，正确处理中文、逗号、引号和换行，并对以 `= + - @` 等公式标记开头的用户文本做文本化防护。JSON 保留字段原值和数组。两种格式都只有本家庭清单，含位置、数量、状态、确认时间等字段及是否有照片，不包含照片文件、私有磁盘路径、账号凭据或邀请码。**导出清单不是完整备份，本轮不提供导入功能。**

## 筛选、请求与删除可靠性

以下规则已随 `2026-11-05-m3.5-reliability` 上线：

- **筛选失败不误操作**：列表数据绑定读取成功时的搜索词、在用／归档状态及隔层。新筛选未成功加载时，旧结果会明确标为上次结果，只能查看；批量选择、全选、批量操作和导出禁用。失败清空选择及相关确认窗，当前筛选重试成功后才恢复操作，旧响应不能恢复错误范围的可信状态。
- **请求有明确期限**：普通读取默认 15 秒，写入默认 30 秒，计时覆盖请求及 JSON 正文读取。成功状态但正文为空、HTML 或无效 JSON 会报错；合法 204 正常处理。超时或网络断开时，写入结果可能尚未确认，应先刷新核对，不自动重试写入。
- **登录失效保持位置**：当前登录的受保护接口返回 401 后，会统一清空旧用户界面并提示重新登录，保留安全的内部页面路径和查询参数。登录成功、退出及改密码等操作会更新认证代次；旧请求的迟到 401 不会退出新登录，并发 401 只触发一次。登录密码错误、加入失败和初次未登录不误触发过期。
- **删除需重新核对**：房间与容器删除必须带用户确认时的 `expected_version`。版本冲突、网络失败或结果不确定时，只加载最新数据并要求再次确认，不自动重放删除。旧客户端缺少该参数会收到 422，需刷新页面加载新版后操作；陈旧版本返回 409。
- **房间版本包含布局变化**：容器新增、修改、删除、换房间及隔层改名都会更新相关房间版本；无实际变化不增加版本。容器删除成功后刷新当前房间版本；旧确认或已打开的房间草稿不会自动升级版本以绕过冲突。旧写接口取得事务写锁后，再用同一连接复核会话、家庭及管理员权限。

照片快捷上传继续使用 **30 秒无新增字节、90 秒服务器确认、10 分钟整次传输上限**，行为不变。详情中的已有照片替换使用 90 秒请求期限；批量操作和导出各自保留 30 秒期限，批量操作仍可用同一操作编号原样复核。

## 拍照上传进度

以下行为已随 `2026-11-05-m3.3-upload-progress` 上线，替代上一版固定 90 秒的整次等待规则：

- **先处理照片**：选图后显示「正在处理照片…」，可以取消或换图，处理完成前不能保存旧照片。原图支持 JPEG / PNG / WebP、25 MiB 和 2000 万像素以内；浏览器尝试缩至长边 1600 像素并以 JPEG 质量 0.82 编码，仅结果更小时使用，实际上传不超过 8 MiB。长边不超过 1600 且不超过 400 KiB 的照片保持原文件。处理后显示原照片和待上传大小；原样重试复用同一个处理后的文件，不重复压缩。
- **看真实进度**：上传百分比、已发送量、总量、平均速度和耗时来自浏览器上传事件与实际计时；总量不可计算时不显示虚构百分比。点击保存后，手机会自动把上传状态和「停止等待」按钮滚动到可见区域。超过 10 秒没有新增上传进度时，提示已经停留多久，可继续等待或停止等待，不据此断言挂死。
- **区分传完与保存成功**：照片传完显示「照片已传完，等待服务器确认保存」，此时仍可停止等待。只有收到业务成功响应才显示已登记。
- **按阶段结束等待**：上传阶段连续 **30 秒没有新增字节**时结束等待；持续缓慢但有新增字节的上传可以超过 90 秒。上传完成后等待服务器确认最多 **90 秒**，整次传输总上限 **10 分钟**。结束等待或手动停止后保留照片、名称、位置和操作编号；保持内容不变再重试，会核对同一次登记。修改内容或换照片会创建新的操作编号。

停止等待不是撤销服务器写入，也不能说明照片没有保存。当前改善了传输量和过程可见性；真实手机、当前网络及代理链路仍需结合实际表现判断，不能用本地慢网测试替代用户现场验证。

## 账号与家庭

从「空间」或「家庭找物」顶部的「账号」进入独立设置页。本地路径为 `/settings`，部署前缀下为 `/wuwei/settings`。登录页的加入入口打开 `/join`（部署后为 `/wuwei/join`）；这些路径均支持直接打开和刷新。

普通成员没有邀请、移除成员或房间修改权限；楼层数据和既有归属保留，暂不增加楼层管理入口。

## 备份、校验与恢复

数据目录包含 `wuwei.db` 和 `media/`。`scripts/backup.py` 仅依赖 Python 标准库，使用 SQLite 在线备份接口读取已提交的 WAL 数据，并复制照片；输出备份目录内包含数据库、照片和记录大小及 SHA-256 的 `manifest.json`。

每次备份完成前都会检查 SQLite 完整性、外键、文件校验和以及数据库引用的照片。若备份期间照片被替换导致文件缺失，本次备份失败并清理临时目录，应重新执行。默认保留 14 天，只清理目标目录内通过校验的过期备份。

Linux 手动备份示例：

```bash
python3 /opt/wuwei/current/scripts/backup.py backup \
  --data-dir /var/lib/wuwei \
  --destination /var/backups/wuwei \
  --keep-days 14
```

成功时输出 JSON，其中 `backup` 是本次备份的完整路径。将下面的路径替换为实际输出的备份目录，再运行校验或恢复：

```bash
BACKUP_BUNDLE='/var/backups/wuwei/wuwei-实际时间-随机值'
python3 /opt/wuwei/current/scripts/backup.py verify "$BACKUP_BUNDLE"
python3 /opt/wuwei/current/scripts/backup.py restore "$BACKUP_BUNDLE" \
  --target /var/lib/wuwei-restore-check
```

`verify` 校验整个备份；`restore` 先校验，再复制到一个**尚不存在的新目录**，复制后再次核验。目标已存在时拒绝执行，即使它是空目录；恢复命令不会覆盖当前数据库，也不会自动切换应用。Windows 可用 `python .\scripts\backup.py` 调用相同子命令和参数。执行账户需要能读取源目录及写入目标父目录；服务器示例目录通常需要管理员权限。

正式恢复时，先恢复到新目录并核验物品、位置和照片，再停止应用，保留旧数据目录，配置应用改用恢复目录后启动。需要同时调整应用与备份 service 的 `WUWEI_DATA_DIR`、`ReadWritePaths`，并确保运行账户对恢复目录有权限。上线迁移前应先生成并验证备份；部署脚本的代码回滚不会恢复数据库。

Linux 包装脚本 `scripts/backup.sh` 可通过 `WUWEI_DATA_DIR`、`WUWEI_BACKUP_DIR`、`WUWEI_BACKUP_KEEP_DAYS` 设置源目录、备份目录及保留天数，默认分别为 `/var/lib/wuwei`、`/var/backups/wuwei`、`14`。

## 每日备份 timer

2026-11-04 的发布已在服务器安装并启用 `wuwei-backup.service` 与 `wuwei-backup.timer`；2026-11-05 的 `m3.5-reliability` 发布后备份再次成功，退出码为 0，timer 保持启用。部署脚本在发布预检和冒烟通过后启用每日计划，并立即运行一次备份。备份目录为 `wuwei:wuwei`、0700，服务以 `wuwei` 账户运行。

模板按服务器本地时区每天 03:15 触发，并随机延迟最多 15 分钟；`Persistent=true` 会在恢复运行后补执行错过的任务。保留期限在 service 的环境变量中配置。数据目录在 systemd 沙箱内可写，以允许 SQLite 使用 WAL 共享内存；备份脚本仍以 `mode=ro` 打开源数据库。

既有线上实例若手动安装，先将本版本脚本和模板放到实际 release，并核对路径，然后执行：

```bash
sudo install -d -o wuwei -g wuwei -m 0700 /var/backups/wuwei
sudo install -m 0644 /opt/wuwei/current/deploy/wuwei-backup.service /etc/systemd/system/wuwei-backup.service
sudo install -m 0644 /opt/wuwei/current/deploy/wuwei-backup.timer /etc/systemd/system/wuwei-backup.timer
sudo systemctl daemon-reload
sudo systemctl start wuwei-backup.service
sudo systemctl status wuwei-backup.service --no-pager
sudo journalctl -u wuwei-backup.service -n 50 --no-pager
```

确认首次备份成功，并用 `verify` 校验日志中返回的备份目录后，再启用计划：

```bash
sudo systemctl enable --now wuwei-backup.timer
sudo systemctl list-timers wuwei-backup.timer --all
```

已有 root 所有的历史备份需要另行检查访问权限。定时任务失败可用 `journalctl -u wuwei-backup.service` 查看原因；启用 timer 本身不代表已有一份可用备份。

## 部署边界

部署入口 `scripts/deploy.ps1` 从脚本位置确定工作区，使用 SSH 主机别名 `bd-a`，必须显式传入新的 release 版本。只允许干净且已有提交的 Git 工作区；`npm ci` 后构建 `/wuwei/` 前端，并再次确认工作区和提交未变化。发布包携带 `REVISION` 与依赖锁，每个 `/opt/wuwei/releases/<版本>/.venv` 按哈希独立安装，静态预检通过后再切换服务。

发布在服务器后台执行，SSH断开不会停止任务。`Start`绑定版本、提交和包SHA；`Status`只查询，`Resume`使用服务器保留的原包，不要求当前工作区仍是该提交。可用以下命令（替换版本）：

```powershell
.\scripts\deploy.ps1 -Version '新的版本' -Action Start -WaitSeconds 0
.\scripts\deploy.ps1 -Version '新的版本' -Action Status -LogLines 40
.\scripts\deploy.ps1 -Version '新的版本' -Action Resume -WaitSeconds 0
```

状态和日志存于`/opt/wuwei/deployments/<版本>/`，同版本不同包拒绝覆盖。全局锁避免并发切换；首次激活前固定回滚目标和服务配置，重试不能覆盖它们。下载／解压中断和普通发布失败可恢复；若机器在切换期间硬掉电、候选版本已现役但未完成，或其他版本已接管，则保守拒绝自动覆盖，需要先核验状态。

启动、线上预检、冒烟或发布后备份失败时恢复旧链接、原服务配置和旧依赖环境；已有 release 不会被覆盖。原有发布前后备份继续保留，异机备份和通知暂缓。`scripts/verify-release.py` 可只读比较发布前快照、账号状态、记录数、迁移、完整性、资源哈希与 Git 提交；输出不含账号密码或业务内容。

- `deploy/wuwei.service`：应用监听 `127.0.0.1:8790`，数据默认位于 `/var/lib/wuwei`。
- `deploy/wuwei-tailnet.service`：以一次性命令持久设置 Tailnet HTTPS 443 的 `/wuwei`，仅供已连接 Tailscale 的设备访问；保留 443 原有 `/` 到 `127.0.0.1:7863` 的服务。
- `deploy/wuwei-funnel.service`：保留 HTTPS 8443 上的公网 `/wuwei` 入口。
- `scripts/preflight.sh`：静态预检核对内网和公网路由；`--live` 增加本地及线上健康检查。
- `scripts/smoke.sh`：检查健康接口、初始化状态、未授权访问、首页及安全响应头。

部署前需要核对目标主机、release 版本、Python 环境、域名和来源配置，并准备经校验的数据备份。部署成功后应检查 timer 的下次执行时间和首次备份结果。

可靠性版本历史核验见 [部署记录](docs/deployment-reliability-2026-11-05.md)。生产不执行真实账号撤销、物品删除或清单导出作为测试。

两个入口的允许来源分别为 `https://bd-a.tail3c54de.ts.net` 和 `https://bd-a.tail3c54de.ts.net:8443`。本机经内网 HTTPS 访问健康接口、页面及 JS/CSS 均成功，证书校验通过；两个合法来源通过 Origin 校验，不可信来源返回 403。没有使用真实账号执行登录，线上浏览器访问仍被现有权限策略阻止，未绕过。本机在 Tailnet 内访问旧 8443 地址仍可能超时，应使用无端口入口，本次没有修改网络 ACL。

账号版本的公网预检与冒烟通过，Tailnet 的 `/settings`、`/join` 返回页面，未登录访问账号接口返回 401；数据库迁移、数据保留、资源哈希、管理命令 `--help` 及发布后备份均已核验。没有使用真实账号生成邀请、加入家庭、移除成员或改密码作为测试。前版证据和验证边界见 [账号版本部署记录](docs/deployment-accounts-2026-11-05.md)。

手机入口版本的内网、公网预检与冒烟通过；当时 Tailnet 的 manifest 和图标返回正确 MIME，位置深链接返回应用页面，容器位置与隔层解析接口未登录均返回 401。迁移 `006`、既有业务数据与账号保留、代码资源哈希及发布后备份均已核验，检查范围内未发现应用错误日志。详见 [手机入口部署记录](docs/deployment-mobile-2026-11-05.md)。该历史记录不代替本轮可靠性版本的发布核验；真实手机摄像头和系统桌面安装仍未实机验收。

## 权限与安全

所有业务接口要求登录并检查家庭归属。密码使用 Argon2id；登录失败达到限制后暂时锁定，同一用户名的首尾空格不会绕过限流。线上 Cookie 为 HttpOnly、Secure、SameSite=Lax，写接口检查 Origin，并设置 CSP、HSTS、X-Frame-Options 和 nosniff。照片使用鉴权接口，`/media` 不公开挂载。

请求响应提供`X-Request-ID`与`Server-Timing`；结构化请求日志只记录路由模板、方法、状态、编号和服务端耗时，不记录查询词、物品ID、正文、照片或凭据。生产关闭会记录完整URL的默认访问日志。`body_receive_ms`表示应用开始接收至正文完整的时间，`after_body_ms`表示正文完整至响应头的时间；不等同于完整手机网络传输时间。

## 缩略图维护

默认只预览超过24小时、数据库不再引用的受管缩略图，显式`--apply`才删除。已归档物品的照片引用仍保留；原照片、数据库、未知文件和符号链接不清理，无自动清理定时器。

```bash
sudo -u wuwei wuwei-admin clean-thumbnails --data-dir /var/lib/wuwei
sudo -u wuwei wuwei-admin clean-thumbnails --data-dir /var/lib/wuwei --apply
```
